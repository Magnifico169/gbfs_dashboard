# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версионирование — [SemVer](https://semver.org/lang/ru/). Релизов пока нет.

## [Unreleased]

### Added
- M1: приём данных на Python (`services/api`): опрос GBFS с ETag и повторами, нормализация v1.1/v2/v3 pydantic-схемами, валидация с карантином, запись только изменившихся станций, SCD2 для справочника станций, журнал `app.ingest_run`. Вся работа с БД — через ORM SQLAlchemy.
- Слоистая структура приложения: `core` (настройки в `core/config/settings.py`, singleton подключения к БД), `models`, `schemas`, `repositories`, `services`, `clients`, `api`; воркер приёма и FastAPI (`/livez`, `/readyz`) в одном приложении.
- Схема PostgreSQL (`core`, `mart`, `app`) описана ORM-моделями; ревизия Alembic сгенерирована по ним и дополнена схемами, суточными партициями `core.station_status`, ролями `app_ingest`/`app_api` и грантами. Сервисы compose: `migrate`, `ingest` (роль `app_ingest`), `api` (роль `app_api`).
- uv-воркспейс, `uv.lock`, `.python-version`.
- Фикстуры: урезанный фид Citi Bike v2.3 и синтетический v3.0 (Citi Bike v3 не публикует); тесты pytest, включая интеграционные с PostgreSQL и проверку проб.
- ADR-0003: приём данных на Python, R — только аналитика.
- ADR-0002 (итерация M0, принят): языки R/Python, хранилище PostgreSQL 18, владение данными, pipeline, функции ролей, обработка ошибок оператора, цель по нагрузке — 1000+ одновременных пользователей.
- Роль оператора уточнена: только справка по станциям и обзор зоны; задачи и эскалации с сервисом не связаны.
- Роль менеджера уточнена: аналитика загрузки, индикаторы и прогноз; задачи и бригады — во внешней системе, в проект не входят.
- `docker-compose.yml` с PostgreSQL 18, healthcheck и шаблон `.env.example`.
- Статический анализ в GitHub Actions: ruff (Python) и lintr (R), настройки в `pyproject.toml` и `.lintr`.
- README: структура проекта, возможности, запуск, план вех.

### Changed
- ruff: отключены RUF001–003 (кириллица) и RUF012 для моделей SQLAlchemy.
- Язык обработки данных — R (в первой версии концепта ошибочно значился Rust).
- Цель по нагрузке пересмотрена: вместо «сотен тысяч RPS» — устойчивость при 1000+ одновременных пользователей.
- Хранилище: ClickHouse отложен до результатов нагрузочного замера, всё хранится в PostgreSQL 18.
