Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версионирование — [SemVer](https://semver.org/lang/ru/). Релизов пока нет.

## [Unreleased]

### Added
- Самостоятельная регистрация через `/register` и `POST /api/v1/auth/register`: все новые аккаунты — операторы, выбор системы, подтверждение пароля в форме, автовход; изменение ролей остаётся у администратора. Общий лимит с входом, аудит и защита от дублирующихся логинов.
- M4: серверный интерфейс Jinja/HTMX, вход с HttpOnly-cookie, обновление и завершение сеанса; защита браузерных POST и request_id ошибок.
- Экран оператора: поиск по названию/адресу/ID, карта зоны, приоритеты проблем, карточка и ближайшие доступные станции, суточный график, события, SSE с backoff/jitter и опросом.
- M5: отчёты по календарным и произвольным интервалам, сравнение, сортируемый рейтинг, CSV и печать в PDF; графики uPlot, среднее и полосы Боллинджера на клиенте.
- Миграция `0004`: R-аналитика внимания/профилей и прогнозов с RLS; покрытие электрического парка в ролл-апах. Прогноз требует достаточной свежей истории.
- API отчёта `/api/v1/systems/{system_id}/report`: непересекающиеся уровни, дочитывание краёв до 10 минут, явная пометка пропорциональной оценки неполных корзин.
- Проверки M4/M5: браузерные роли и зоны, cookie/CSRF, CSV, взвешенные показатели, DST, пропуски графиков и достаточность истории прогноза.
- M3: собственные логины с Argon2id, короткие JWT, ротация и отзыв refresh-сеансов, ограничение попыток входа.
- Пользователи, роли, зоны по регионам и назначения; административный API, аудит и команда создания первого администратора.
- Миграция `0003`: RLS и отдельные роли PostgreSQL для оператора, менеджера и администратора; менеджеру закрыты сырые состояния.
- Изоляция кэша и SSE по роли и зоне, закрытие SSE по истечении токена; интеграционные проверки доступа и конкурентной ротации.
- M2: API чтения `/api/v1`, SSE-снимки/дельты через `LISTEN/NOTIFY`, TTL-кэш и защита от перегрузки.
- События из дельт и `observed_until` для интервалов подтверждённого состояния; разрыв связи не порождает фиктивные перемещения.
- R-сервис `analytics`, ролл-апы 10 минут / час / местные сутки, отдельная роль `app_analytics` и миграция `0002_m2`.
- Интеграционные тесты Python/R в CI, нагрузочные сценарии на 1000/10000 пользователей и проверка восстановления после потери БД.
- M1: приём данных на Python (`services/api`): опрос GBFS с ETag и повторами, нормализация v1.1/v2/v3 pydantic-схемами, валидация с карантином, запись только изменившихся станций, SCD2 для справочника станций, журнал `app.ingest_run`. Вся работа с БД — через ORM SQLAlchemy.
- Слоистая структура приложения: `core` (настройки в `core/config/settings.py`, singleton подключения к БД), `models`, `schemas`, `repositories`, `services`, `clients`, `api`; воркер приёма и FastAPI (`/livez`, `/readyz`) в одном приложении.
- Схема PostgreSQL (`core`, `mart`, `app`) описана ORM-моделями; ревизия Alembic сгенерирована по ним и дополнена схемами, суточными партициями `core.station_status`, ролями `app_ingest`/`app_api` и грантами. Сервисы compose: `migrate`, `ingest` (роль `app_ingest`), `api` (роль `app_api`).
- uv-воркспейс, `uv.lock`, `.python-version`.
- Фикстуры: урезанный фид Citi Bike v2.3 и синтетический v3.0 (Citi Bike v3 не публикует); тесты pytest, включая интеграционные с PostgreSQL и проверку проб.
- ADR-0003: приём данных на Python, R — только аналитика.
- ADR-0002 (итерация M0, принят): языки R/Python, хранилище PostgreSQL 18, владение данными, pipeline, функции ролей, обработка ошибок оператора, цель по нагрузке — 1000+ одновременных пользователей.
- Роль оператора уточнена: только справка по станциям и обзор зоны; задачи и эскалации с сервисом не связаны.
- Роль менеджера уточнена: аналитика загрузки, индикаторы и прогноз; задачи и бригады — во внешней системе, в проект не входят.
- `docker-compose.yml` с PostgreSQL 18, healthcheck и шаблон `.env.example`.
- Статический анализ в GitHub Actions: ruff (Python) и lintr (R), настройки в `pyproject.toml` и `.lintr`.
- README: структура проекта, возможности, запуск, план вех.

### Fixed
- Карта OpenStreetMap: политика Referer разрешает отправку адреса сайта для загрузки подложки, сохраняя пути страниц и параметры закрытыми при внешних запросах.
- Обновление ранних установок M1, у которых `alembic_version=0001`, но ещё старые имена ключей: переходная `0002a` перед аутентификацией сохраняет данные, переименовывает ключи/индексы и добавляет служебные метки. Миграция `0005` сохраняет сообщения `app.ingest_run.error` и выравнивает новые базы.

### Changed
- R-ролл-апы загружаются через COPY во временную таблицу и INSERT в mart: прямая запись COPY несовместима с RLS.
- API M2 теперь требует Bearer-токен; пробы остаются публичными. Compose требует `AUTH_SECRET`, нагрузочные сценарии — `BENCH_TOKEN`.
- Отзыв пользовательских прав блокирует обновление сеанса; выданный access-токен действует до `exp` (по умолчанию не более пяти минут).
- ruff: отключены RUF001–003 (кириллица) и RUF012 для моделей SQLAlchemy.
- Язык обработки данных — R (в первой версии концепта ошибочно значился Rust).
- Цель по нагрузке пересмотрена: вместо «сотен тысяч RPS» — устойчивость при 1000+ одновременных пользователей.
- Хранилище: ClickHouse отложен до результатов нагрузочного замера, всё хранится в PostgreSQL 18.
