# M2: API чтения, события, ролл-апы и SSE

## Запуск и миграция

`docker compose up -d --build --wait` применяет новую миграцию `0002` поверх M1 и запускает `analytics` вместе с API и приёмом. Миграция M1 уже в main и не изменяется. Роль `app_analytics` читает `core`, пишет только `mart`; `app_ingest` больше не пишет в `mart`. SQLAlchemy описывает схему, Alembic управляет ею; R получает данные через DBI/RPostgres и записывает результаты через COPY.

## API

Базовый путь — `/api/v1`. Идентификатор системы обязателен во всех запросах её данных.

- `GET /systems` — системы и часовые пояса.
- `GET /systems/{system_id}/stations?limit=100&after=...&region_id=...` — действующие SCD2-версии и текущее состояние. Максимум 500 строк; `next_after` передаётся следующему запросу.
- `GET /systems/{system_id}/stations/{station_id}` — одна действующая станция.
- `GET /systems/{system_id}/stations/{station_id}/history?start=...&end=...` — факты изменения/разрыва наблюдений; максимум 90 дней, курсор `next_before` передаётся как `before`.
- `GET /systems/{system_id}/stations/{station_id}/events` — события, обратный порядок `id`, курсор `before`.
- `GET /systems/{system_id}/stations/{station_id}/rollups?start=...&end=...&resolution=auto` — агрегаты. Уровни: `10m`, `hour`, `day`; `auto` выбирает уровень примерно до 1000 точек. Более 1000 точек на явно выбранном уровне возвращают 422.
- `GET /systems/{system_id}/stream` — SSE.

`start` и `end` — ISO 8601 с часовым поясом, интервал `[start, end)`. M2 возвращает **целые пересекающиеся корзины** ролл-апов: фактические границы указаны в `bucket_start`/`bucket_end`, политика — `bounds=whole_intersecting_buckets`. Частичный последний бакет может ещё дополняться; `processed_until` показывает границу обработки. Точные произвольные отчётные интервалы с дочитыванием краёв относятся к отчётам M5.

У текущего состояния есть `quality`: `fresh`, `stale`, `unknown`, `invalid`. Нет состояния или `reported_at` — `unknown`; устаревший источник/опрос — `stale`; более свежий карантин — `invalid`. Сохранённые числа не подменяются нулями. `as_of`, `checked_at`, `reported_at` и `age_seconds` позволяют показывать возраст. После исчезновения станции из справочника текущий список её не показывает, история остаётся доступной.

404 означает неизвестную систему/станцию; 422 — неверный интервал/параметры; 503 с `Retry-After: 3` — недоступность БД или перегрузку. Кэш может отдать прежний результат в течение своего TTL. `/livez` не зависит от БД, `/readyz` проверяет подключение. С M3 данные требуют Bearer-токен и фильтруются по зоне; матрица ролей и ограничения доступа к истории — в [m3.md](m3.md).

## События и достоверность

Приём пишет снимок, текущее состояние, события и `NOTIFY snapshot_ready` одной транзакцией. Откат не публикует сигнал. `bikes_added`/`bikes_removed` — нижняя оценка перемещений по разности счётчиков, а не доказанные аренды: обслуживание и перераспределение тоже меняют счётчики. Также фиксируются переходы пусто/не пусто, полно/не полно, установки, аренды и возврата.

Первый снимок и восстановление после перерыва не создают выдуманных перемещений. `observed_until` в факте продлевается при подтверждении неизменившегося состояния. Разрыв связи создаёт новый факт даже при совпавших счётчиках. Ответ 304 подтверждает только станции последнего принятого снимка и не обновляет исходный `reported_at`.

## Ролл-апы

R пересчитывает данные каждые 600 секунд, порциями до двух местных суток и пакетами до 100 станций. Advisory lock предотвращает двух писателей одной системы; замена результатов и продвижение курсора атомарны. Повтор пересчитывает текущие/пограничные сутки, не прибавляет дубли. Сбой системы не останавливает обработку остальных.

Состояние действует до следующего факта или `observed_until + STALE_AFTER_S`, что раньше. Неизвестное время не попадает в суммы. Результат хранит `observed_seconds`, взвешенные `bikes_seconds`/`docks_seconds`, отдельное покрытие доков, min/max, длительность пустоты/полноты, число фактов `samples` и нижние оценки перемещений. Среднее клиент вычисляет делением суммы на соответствующее покрытие; нулевое покрытие означает отсутствие достоверной оценки. Неполная история не дополняется нулями.

Суточные границы берутся из часового пояса системы. DST даёт 23/25-часовые сутки; повторы локального часа имеют разные UTC-метки. `STALE_AFTER_S` должен совпадать у API, приёма и аналитики; Compose задаёт его всем трём. Старые факты M1 имеют подтверждение только на момент записи — миграция не выдумывает историю опросов.

## SSE и нагрузка

Один LISTEN на процесс API обслуживает все соединения. Первое сообщение `snapshot` содержит текущее состояние; далее `delta` содержит изменённые станции и `removed`. Переподключение, включая `Last-Event-ID`, всегда начинается новым снимком: NOTIFY не является журналом воспроизведения. Сообщение `reset` требует переподключения. `unavailable` означает, что обновление временно невозможно; последнее состояние остаётся у клиента с прежним временем.

Heartbeat — каждые 15 секунд. После пропущенного уведомления/переподключения LISTEN данные пересверяются через TTL. Очередь клиента ограничена 16 сообщениями; медленный клиент получает reset и закрывается. Лимит — 2000 SSE-клиентов на процесс. HTTP имеет отдельный лимит 128 одновременно обрабатываемых запросов. Тяжёлые запросы истории/ролл-апов используют отдельный пул из двух соединений. Одинаковые запросы к БД объединяются, кэш ограничен 256 записями и TTL 3 секунды.

Compose задаёт `nofile=65536`. При локальной нагрузке требуется `ulimit -n 32768` у API и генератора. Масштабирование API — несколькими процессами/репликами; каждый слушает PostgreSQL и рассылает своим клиентам.
