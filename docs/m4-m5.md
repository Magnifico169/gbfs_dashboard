# M4/M5: оператор и менеджер

## Запуск

`docker compose up -d --build --wait` применяет миграции до `0005` и обновляет API и analytics.
Ранние базы M1 с прежними именами ключей автоматически приводятся к ORM-схеме миграцией
`0002a` перед `0003`: записи и ключи сохраняются, недостающие created_at/updated_at получают
время обновления схемы. Даты исходных наблюдений не меняются. Возврат с `0002a` к `0002`
не возвращает старые имена, поскольку текущая `0001` уже описывает ORM-схему.
Миграция `0005` сохраняет прежние сообщения ошибок приёма в `app.ingest_run.error` и добавляет
этот nullable-столбец в базы, где его ещё нет. Удалять том БД или выполнять `alembic stamp` не нужно.
Откройте `http://localhost:8000`. Пользователи регистрируются через `/register` как операторы выбранной системы.
Роли и зоны изменяются административным API M3;
интерфейс администратора остаётся M6. В форме входа нужен `system_id` назначенной системы.
Администратор может входить без системы и выбирать её в экране.

Интерфейс находится в `services/api/app/web/` и входит в Python-пакет и Docker-образ.
Jinja рендерит HTML; HTMX обновляет фрагменты. uPlot строит графики, Leaflet — карту.
Версии библиотек закреплены и сохранены вместе с лицензиями в `static/vendor/`.
Сборка Node для запуска не нужна. Только картографическая подложка загружается с OpenStreetMap;
список станций работает без неё. Производственную карту с большим трафиком следует обеспечивать
своим поставщиком тайлов с подходящими условиями использования.

## Сеанс и права

Браузерные маршруты `/ui/` принимают короткий JWT из HttpOnly-cookie; JSON API по-прежнему
требует Bearer и не принимает браузерные cookie. Refresh-cookie доступна только `/ui/`.
Обе cookie имеют SameSite=Strict, а при HTTPS — Secure. HTTPS-прокси должен передавать схему
запроса доверенным способом в Uvicorn. Пароли и токены не передаются в URL или localStorage.
HTMX не сохраняет HTML истории в localStorage. Ответы страниц и API имеют Cache-Control: no-store.

POST проверяет Origin и Sec-Fetch-Site. Ограничение входа общее для HTML-формы и JSON API.
По истечении JWT браузер обновляет сеанс через POST `/ui/refresh` и перезагружает страницу,
перечитывая права; запросы обновления в одной вкладке объединяются, между вкладками используются
Web Locks при поддержке браузером. Ошибка обновления 401/403 возвращает к входу.
Выход отзывает refresh-сеанс и удаляет cookie. Максимальная задержка отзыва уже выданного JWT
остаётся как в M3. Проверка роли выполняется сервером; данные читаются в контексте RLS.

Все ответы получают X-Request-ID. Ошибки HTML показывают код, текст и request_id;
при ошибке фонового обновления сохраняются последние значения с предупреждением.
Чужая станция по-прежнему неотличима от несуществующей.

## Оператор

`/ui/operator` показывает только свою зону: счётчики, поиск по названию/адресу/ID, фильтр
проблем, список по критичности (100 строк на страницу), карту и 20 последних событий.
Карточка `/ui/operator/station` содержит обычный/электрический транспорт, свободные и
неисправные места, флаги аренды/возврата, возраст, ближайшие доступные станции по прямой,
суточный график 10-минутных средних и события с курсором. Карточка обновляется каждые 30 секунд.
Объявления о работах не выдумываются: текущая модель источника их не содержит, это указано явно.

Состояния «пусто», «потеряна связь», «нет данных», «данные недостоверны» различаются.
Известные, но устаревшие счётчики подписаны как последние известные; они не входят в доступное
к аренде и в рекомендации ближайших станций. Указаны времена источника и проверки.

`/ui/stream` использует тот же SSE-сервис, что API. Снимки и дельты вызывают HTMX-обновление
из общего кэша, частые дельты объединяются. reset/unavailable/обрыв приводят к повтору с
экспоненциальной задержкой и jitter (до примерно 30 секунд); опрос каждые 30 секунд также
проверяет возраст данных и служит резервом. Старые значения не выдаются за новые при сбое.

## Отчёт менеджера

`/ui/manager`: вся зона или выбранная станция, сутки, неделя, календарный месяц,
3/6/9/12 месяцев и произвольные даты. Без смещения даты интерпретируются в часовом поясе
системы. Неоднозначные/несуществующие часы DST отклоняются: используйте ISO 8601 со смещением.
Конец не включается. Можно сравнить с непосредственно предшествующим интервалом той же
длительности; его ряд сдвигается на длину периода. Отсутствующая история не заполняется нулями.

JSON: `GET /api/v1/systems/{system_id}/report?start=...&end=...&station_id=...`.
Без station_id возвращается вся доступная зона. Ограничение — 3660 дней.
Отчёт использует отдельный пул и очередь тяжёлых чтений, TTL-кэш включает роль, систему и зону.
Сырые состояния и SSE менеджеру недоступны, в том числе на уровне PostgreSQL.

Уровень выбирается автоматически: 10 минут до 998 таких интервалов, затем час до 998 часов,
затем местные сутки. Внутри выбранного диапазона используются только непересекающиеся корзины;
края дочитываются с часового/10-минутного уровня. На переходах DST сутки имеют 23/25 часов.
Неполная 10-минутная корзина оценивается пропорционально пересечению и отмечается `estimated`.
Это **оценка**, а не точное восстановление событий внутри 10 минут; точные произвольные границы
из существующих агрегатов получить нельзя. Политика `bounds=clipped_10m_edges` отличается
от старого API M2, который продолжает возвращать целые пересекающиеся корзины.

Средние считаются по суммам и времени наблюдений, для доков — по их отдельному покрытию.
Нулевое покрытие означает неизвестное среднее. Сеть показывает среднее на наблюдаемую станцию,
простои — в станция-часах. Оборот является нижней оценкой перемещений счётчиков, включая
обслуживание и перераспределение, и не означает число аренд.

Графики строятся браузером: доступность, среднее за 20 точек и полосы Боллинджера ±2σ,
часовой спрос, профиль по дням недели, прогноз, доля электрических. Разрывы наблюдений
разрывают линии и окно индикатора. Спрос по часам доступен только до часовой гранулярности.
Рейтинг по умолчанию сортируется по обороту на место; заголовки переключают сортировку.
Вместимость для нормировки берётся из действующего справочника, что указано в интерфейсе.

CSV `/ui/report.csv` содержит выбранный ряд, запрошенные границы, часовой пояс, покрытие,
уровень, processed_until и пометки точности. «Печать / PDF» открывает штатную печать браузера
с отдельными стилями: выберите сохранение в PDF. Это интерактивный экспорт; отчёты по расписанию
и серверная генерация PDF не входят в эти экраны.

## R-аналитика

Миграция `0004` добавляет `mart.station_insight` (срез внимания и часовой профиль в JSONB)
и `mart.load_forecast` (прогноз на момент anchor). Только app_analytics может писать;
пользовательские роли читают через RLS текущей зоны. Профиль и внимание хранятся вместе,
поскольку рассчитываются одним проходом и обновляются одной транзакцией.

После обработки ролл-апов R пересчитывает срез и профиль за последние 28 дней. Внимание:
нехватка транспорта от 10 минут суммарно за последний завершённый час, переполнение,
неисправности и запрет аренды. Это отдельный текущий срез, не состояние на историческую дату
отчёта. API продолжает увеличивать возраст среза при остановке аналитики; свежесть не замирает.
Профили взвешены по времени наблюдений, часы/дни недели — местные.

Прогноз: до шести следующих часов, среднее исторического часа с поправкой на отклонение
последнего часа, затухающей с горизонтом. Диапазон ±1.96 стандартного отклонения — эмпирический,
не обещание точности. Нужно не менее 7 наблюдаемых дней, 3 наблюдения каждого часа с покрытием
не менее 30 минут и достаточно свежий последний час. При недостатке данных линия не рисуется.
Исторический отчёт выбирает только сохранённый anchor не позднее конца отчёта и не старше часа;
точки до конца отчёта отбрасываются. Прогнозы старше 90 дней удаляются. Пересчёт с тем же anchor
идемпотентен; транзакционная advisory-блокировка исключает одновременных писателей системы.

Ролл-апы дополнены временем наблюдений и суммами электрического состава. Старые записи имеют
нулевое покрытие нового показателя — история электрического парка не выдумывается; обычный
пересчёт постепенно добавляет его там, где сохранились исходные факты.

## Проверки

- `cd services/api && uv run pytest`: M1–M5, реальные миграции PostgreSQL, RLS, формы, ошибки,
  обновление cookie, CSRF, CSV, границы интервалов и DST.
- `node --test services/api/tests/test_chart_math.cjs`: неизвестное покрытие, разрывы и индикатор.
- Из `services/analytics`: `Rscript tests/test_rollups.R`, `Rscript tests/test_insights.R`,
  `Rscript tests/test_database.R` (последний требует БД с миграциями).
- `ruff check .`, `ruff format --check .`, lintr.
